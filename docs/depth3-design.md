# Depth 3 (지역 상세) — 매물종류별 설계

> 작성: 2026-05-31 · 상태: 설계 초안(문서)
> 관련: `docs/known-issues.md`(KI-4·8·10·16), 제품 컨셉 §0(지역 우선 추천)
> 목적: Depth 3를 "아파트 단지 예측" 중심에서 **"동 상세 평가" 중심**으로 재정의하고,
>       아파트 외 매물종류에서도 의미 있는 상세 화면을 제공하기 위한 설계 정리.

---

## 0. 배경 / 현재 동작

- **제품 컨셉(§0)**: 개별 매물이 아니라 **지역(행정동)을 먼저 추천**. Depth 1·2 = 동 단위 4축 점수 추천.
- **현재 Depth 3** (`GET /api/regions/:legalDongCode/complexes`, `regions.ts`):
  - 행정동 → 아파트 **단지 리스트** + 단지별 최근 1년 거래가 + **3년 가격 전망**(`predictedPricePerM2_3y`, LSTM/ARIMA) + `confidence`.
  - 코드 주석 명시: *"단지 카드는 APT/SALE 만 흐름. VILLA/OFFICETEL/JEONSE 는 Phase 3 까지 비활성."*
  - 즉 **Depth 3 전체가 아파트-단지 중심**이고, 비아파트는 사실상 빈 화면.

---

## 1. 문제 정의 — 왜 비아파트는 단지 예측이 안 되나

표면적으로는 "아파트 외 매물은 동 단위 거래가로 들어온다"는 데이터 형태 문제로 보이지만,
근본 원인은 **학습 가능한 시계열 단위의 부재**다.

실제 국토부 RTMS API 응답 컬럼(부록 A)을 보면, 비아파트는 **두 그룹**으로 명확히 갈린다.

- **아파트**: *단지 × 평형*이라는 동질적·반복거래 단위가 존재 + `t_apt_complex`에 좌표 보유 → 같은 단위 가격이 시간에 따라 반복 관측 → 시계열(LSTM/ARIMA) 성립. ✅

- **단독·다가구 (SHTrade/SHRent)** — **식별 자체가 동 단위** ❌
  - 매매: `jibun`이 `5**`로 **마스킹**, `totalFloorAr`(연면적)·`plottageAr`(대지면적)만, 단지명·좌표 없음.
  - 전월세: `jibun` **아예 없음**, 연면적만.
  - → 식별 키가 `동(umdNm) + 건축년도 + 연면적`뿐 → 매물/건물 단위 개념이 성립 안 함.
  - 면적이 **연면적**이라 전용면적 비교도 불가(KI-16 caveat 실증).

- **연립다세대(빌라)·오피스텔 (RHTrade/RHRent)** — **건물 식별은 가능, 시계열은 비신뢰** ⚠️
  - `mhouseNm`(건물명, 예: 럭키평창빌라) + `jibun` + `floor` + `excluUseAr`(전용면적) 보유 → 개별 호실 수준 식별 가능.
  - 그러나 (a) ~~좌표 없음~~ → **2026-05-31 해소**: `geocode:complexes`로 `t_offi/villa_complex.lat/lng` 백필
    (OFFI ~99.98%·bbox 오매칭 0, VILLA 진행 중). (b) **건물당 반복거래 희소**(시계열 표본 부족), (c) **건물명 표기 비일관**(같은 건물 다른 표기) → 매물 시계열 학습은 *불가*가 아니라 *신뢰 부족*.

- **이질성 실증**: RH 매매 응답에 `floor = -1`(반지하)이 실제로 존재 → 한 동 안에 반지하 ~ 고층이 혼재한다는 근거. 동으로 묶어 단일 "예측값"을 내면 의미를 잃는다.

→ 결론: **세 종류 모두 매물·단지 단위 가격 예측이 부적합**하되 이유가 다름 — 단독·다가구는 *식별이 동 단위*, 빌라·오피스텔은 *식별은 되나 표본·좌표 부족*. 어느 쪽이든 Depth 3는 **현재 시세 "구조(분포)"** 를 보여주는 것이 정직하고, §0 컨셉("좋은 집이 아니라 좋은 지역")과 더 정합적이다.

> **참고**: 빌라·오피스텔은 건물 식별이 되므로, 후속으로 *예측 없는* "건물 최근 시세 카드"는 선택적으로 가능(§5). 단독·다가구는 그조차 불가.

## 2. 설계 원칙

1. **Depth 3의 본체 = "동 상세 평가"** — 모든 매물종류 공통. 제품 컨셉과 정합.
2. **시계열 가격 전망 = 데이터가 받쳐주는 아파트에만 붙는 부가 모듈**. 비아파트엔 미표기.
3. **정직성** — 비아파트는 "예측" 대신 시세 **분포/구조**를 제시하고, 전망 미제공 사유를 명시.
4. **기존 자산 재사용** — 이번 사이클에 만든 데이터(POI·median·반전세·안전·교통)가 그대로 코어 재료.

## 3. Depth 3 구성 — 공통 코어 + 종류별 모듈

### 3-A. 공통 코어: "동 상세 평가" (모든 매물종류)

**(A) 4축 점수 근거 분해** — Depth 2 `totalScore`를 펼쳐 신뢰 부여
- 통근: ODsay 실측 통근시간·환승·비용 (+ 교통 품질: 정류장 수·배차·막차)
- 주거비: RIR(소득 대비), median 월주거비, 산출 근거(rent vs sale-proxy)
- 안전: 범죄·가로등·CCTV 분해 (`t_safety_index` 3종 점수)
- 생활: POI 카테고리별 개수 (지하철·마트·편의점·카페·음식점·병원·약국·은행)

**(B) 시세 구조 — 예측이 아니라 "분포"**
- 매매 / 전세 / 월세 **median** (KI-8·16 완료)
- **면적대별(소·중·대) 분리** 시세 (KI-16 후속 — Depth 3에서 표출)
- **표본 N건** 신뢰 칩 (10건 미만 amber, KI-11)
- **반전세 비율** 별도 라벨 (KI-10 후속 — 현재는 통계에서 제외만, Depth 3에서 비율 노출)

**(C) 부가 정보**
- 주변 LH 청년주택 N개, 동 내 단지 수, 거래 활성도(최근 거래 건수)

### 3-B. 종류별 모듈

| 매물종류 | 공통 코어 | 추가 모듈 |
|---|---|---|
| **아파트(APT)** | ✅ | **단지 리스트 + 단지별 3년 가격 전망 + confidence** (현 기능 유지) |
| **빌라(VILLA)** | ✅ | 없음 — 전망 자리에 "매물 단위 데이터 한계로 시세 분포·동 평가 제공" 안내 |
| **오피스텔(OFFI)** | ✅ | 동일 |
| **단독·다가구(SH)** | ✅ | 동일 (+ 면적=연면적 caveat 표기) |

## 5. 후속 작업 (KI 신설/연계 후보)

## 부록 A. RTMS API 응답 컬럼 (식별 근거)

| API | 건물 식별 컬럼 | 면적 | 좌표 | 식별 수준 |
|---|---|---|---|---|
| 아파트 (별도 단지 테이블) | 단지명 + 평형 | 전용 | `t_apt_complex` 보유 | 단지×평형 ✅ |
| 연립다세대 매매 `getRTMSDataSvcRHTrade` | `mhouseNm`(평창스카이빌)·`jibun`(549-3)·`floor`(-1) | `excluUseAr`(전용 75.45) | 없음(지오코딩) | 건물/호실 ⚠️ |
| 연립다세대 전월세 `getRTMSDataSvcRHRent` | `mhouseNm`(럭키평창빌라)·`jibun`(329-2)·`floor`(2) | `excluUseAr`(전용 73.02) | 없음(지오코딩) | 건물/호실 ⚠️ |
| 단독·다가구 매매 `getRTMSDataSvcSHTrade` | `jibun` **마스킹(5\*\*)**, 단지명 없음 | `totalFloorAr`(연면적)·`plottageAr`(대지) | 없음 | 동 단위 ❌ |
| 단독·다가구 전월세 `getRTMSDataSvcSHRent` | `jibun` **없음**, 단지명 없음 | `totalFloorAr`(연면적) | 없음 | 동 단위 ❌ |

- 공통: `sggCd`(시군구 5자리) + `umdNm`(읍면동) + `buildYear` + 거래일/금액.
- `floor = -1`(반지하) 실거래 존재 → 동 내 이질성 실증.
- 빌라·오피는 API에 좌표가 없어 지오코딩 필요했고, **2026-05-31 `geocode:complexes`로 백필 완료**
  (`t_offi/villa_complex.lat/lng`, OFFI ~99.98%·VILLA 진행). 단독·다가구(SH)는 지번 마스킹이라 여전히 동 centroid 근사만.
